## Critical Issues (Fix Now)

1. **`@tanstack/react-query` missing from `node_modules`** — `package.json` (not listed) — 52 files import `@tanstack/react-query` at runtime; `node_modules/@tanstack/react-query` does not exist → `next build` will throw `Cannot find module '@tanstack/react-query'` and fail to produce a production bundle. Add `"@tanstack/react-query": "^5"` to `dependencies` and run `npm install`. — `src/app/dashboard/**/*.tsx` (52 files)

2. **XSS via `dangerouslySetInnerHTML` in content preview** — `src/components/create/content-preview-modal.tsx:83` — The `content` prop is AI-generated HTML piped directly into `dangerouslySetInnerHTML={{ __html: content }}` with no sanitization. Malicious `<script>` or `onerror` attributes in generated output execute in the user's browser. Fix: sanitize with `DOMPurify.sanitize(content)` before rendering.

3. **GraphQL schema introspection unauthenticated** — `src/app/api/graphql/route.ts:8` — The GraphQL route exports `yoga` directly without a route-level auth guard. While resolvers call `context.requireAuth()`, introspection queries (`__schema`, `__type`) enumerate the full schema without authentication. Fix: disable introspection in production (`introspection: process.env.NODE_ENV !== 'production'`) in the yoga config.

4. **Export jobs held in process-scope `Map`** — `src/app/api/export/route.ts:42` — `const exportJobs = new Map<string, ExportJob>()` stores job state in the Node.js process. Under serverless/multi-instance deployments (VPS with multiple containers) job lookups will fail 50–100% of the time. Fix: store export job state in Redis (Upstash is already wired).

5. **Cron routes open without secret when `CRON_SECRET` is unset** — `src/app/api/cron/audit/route.ts:16-21`, `scheduler/route.ts:19-24`, `monitor/route.ts:20-25`, `check-predictions/route.ts:24-29` — If `CRON_SECRET` is not set in the environment, `verifyCronSecret()` returns `true` for all requests in development AND (critically) for production requests when the env var is accidentally unset. Fix: make the check hard-fail when `CRON_SECRET` is absent in `NODE_ENV=production`.

6. **184 TypeScript `any` violations in production code** — `src/app/api/crm/pipeline/route.ts` (7), `src/lib/browser-query/types.ts` (6), `src/hooks/usePlatformDashboard.ts` (5) — TypeScript strict mode is configured but `any` is downgraded to warning in ESLint. 184 live violations erode type safety and hide runtime errors. Each `any` is a potential `undefined is not a function` in production.

7. **`@tanstack/react-query` not in `package.json`** — `package.json` — Package is used extensively (52 imports) but absent from `dependencies`. This means `npm install` in a fresh environment will not install it, and a production build will hard-fail. Paired with #1 above for the same fix.

## Warnings (Fix Soon)

1. **SWR and TanStack Query co-exist across 9 hook files** — `src/hooks/useMarketing.ts`, `useIntegrations.ts`, `usePlatformMonitoring.ts`, `useCRM.ts`, `useSocial.ts`, `usePlatformDashboard.ts`, `useAnalytics.ts`, `useAdmin.ts`, `useSEO.ts` — SWR is listed as a `dependency`; TanStack Query is the intended standard but is missing from `package.json`. Two data-fetching layers create inconsistent cache invalidation, stale-while-revalidate behaviour, and duplicated network requests. Pick one and migrate.

2. **3 stale Clerk environment variables in `docker-compose.yml`** — `docker-compose.yml:30-32` — `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `CLERK_WEBHOOK_SECRET` are still present after the Clerk → Supabase migration. They are no longer used by the application but will confuse future deployments and may cause accidental Clerk SDK initialization if a library auto-detects these env vars.

3. **`0 React.memo` across 242 client components** — `src/components/**/*.tsx` — No client component uses `React.memo`. With React 19 concurrent rendering, large dashboard pages with many sibling components (e.g., `src/app/dashboard/brands/page.tsx` at 1,506 lines) re-render entire subtrees on any state change. Apply `React.memo` to pure, leaf-level components first: score cards, chart wrappers, list items.

4. **Recharts statically imported in 9+ components** — `src/components/engine-room/competitive-radar.tsx:12`, `src/components/dashboard/score-trend.tsx:14`, and 7 others — Recharts is a ~200KB bundle. It is currently eagerly imported, increasing initial parse time for all dashboard pages. The `.auto-claude/specs/024-dynamic-import-recharts-for-200kb-bundle-savings` spec exists but is unimplemented. Fix: wrap each chart component with `next/dynamic({ ssr: false })`.

5. **5 files > 1,200 lines are god-files** — `src/lib/graphql/schema.ts` (2,284), `src/app/dashboard/brands/page.tsx` (1,506), `src/lib/db/queries/competitor-queries.ts` (1,370), `src/lib/billing/local-payments.ts` (1,255), `src/app/dashboard/settings/settings-client.tsx` (1,242) — These files are brittle, hard to test, and slow to type-check. Split `schema.ts` into domain modules; extract sub-components from `brands/page.tsx`.

6. **API routes lack Zod input validation** — only 8 of 305 API routes import Zod. Routes like `src/app/api/crm/pipeline/route.ts`, `src/app/api/webhooks/postiz/route.ts` accept `request.json()` directly. Malformed or missing fields cause uncaught TypeErrors that surface as HTTP 500 instead of HTTP 400. Add `z.object({...}).safeParse(await request.json())` at the top of every POST/PUT handler.

7. **4 raw `<img>` tags bypassing next/image** — `src/app/report/[brandId]/[period]/page.tsx:169`, `src/app/dashboard/brands/new/new-brand-client.tsx:515`, `src/app/dashboard/brands/[id]/edit/page.tsx:494` (+ 1 more) — Raw `<img>` elements skip Next.js image optimization (lazy loading, WebP conversion, CDN caching). Replace with `<Image>` from `next/image` (noting the PDF renderer page may need a special approach).

8. **44 `bg-black` / `#000000` colour violations** — multiple files — Design system forbids pure black backgrounds (`#0a0f1a` is the correct deep-space navy). 44 occurrences in TSX files break visual consistency and will look jarring in the dark theme. Replace with `bg-background` or `bg-[#0a0f1a]`.

9. **35 `backdrop-blur` usages outside modals** — `src/components/landing/*.tsx`, `src/components/mobile-navigation.tsx`, `src/components/command-palette/command-palette.tsx`, and others — Design system reserves glassmorphism/backdrop-blur for modals only. Using it on landing page sections and command palette blurs content behind main UI elements, causing performance and consistency issues.

10. **569 `console.error`/`console.warn` calls in production code** — found across `src/lib/graphql/schema.ts` (45), `src/lib/services/brand-post-create.ts` (13), `src/lib/notifications/service.ts` (11) — Logger (`src/lib/logger.ts`) is available but not consistently used. `console.error` in server-side code bypasses Sentry structured logging and log aggregation. Replace with `logger.error({...}, "message")`.

11. **No Playwright e2e test runs since April 2026** — `e2e/*.spec.ts` — All 205 features self-report `passes:true`, but no automated browser tests have run in 93 days. Silent regressions in routing, auth flows, and UI interactions are probable. Re-enable Playwright CI as a quality gate.
