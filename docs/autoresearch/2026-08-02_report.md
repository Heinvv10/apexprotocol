## Critical Issues (Fix Now)

1. **`@tanstack/react-query` missing from `node_modules` and `package.json`** — `package.json` — 52 source files import `@tanstack/react-query` at runtime; the package is absent from both `dependencies` and `node_modules`. A production `next build` throws `Cannot find module '@tanstack/react-query'` and fails entirely. `@tanstack/react-query-devtools` is present in `devDependencies` but that does not pull the main package. **Fix:** add `"@tanstack/react-query": "^5"` to `dependencies` and run `npm install`. This single fix unblocks production deployment. — **15 weeks unresolved.**

2. **XSS via `dangerouslySetInnerHTML` in content preview** — `src/components/create/content-preview-modal.tsx:83` — `dangerouslySetInnerHTML={{ __html: content }}` renders AI-generated HTML with no sanitization. If an LLM produces `<script>alert(1)</script>` or `<img onerror="...">`, it executes in the victim's browser session. **Fix:** install `dompurify` + `@types/dompurify` and wrap with `DOMPurify.sanitize(content)`. — **12 weeks unresolved.**

3. **GraphQL schema introspection unauthenticated** — `src/app/api/graphql/route.ts:8` — The `yoga` handler is exported directly with no route-level auth guard. Introspection queries (`__schema`, `__type`) enumerate the full API schema (all types, fields, mutations) for any unauthenticated caller. While resolvers may check `context.requireAuth()`, introspection runs before any resolver. **Fix:** set `introspection: process.env.NODE_ENV !== 'production'` in the yoga config. — **Unresolved.**

4. **Export jobs held in process-scope `Map`** — `src/app/api/export/route.ts:42` — `const exportJobs = new Map<string, ExportJob>()` stores state in a single Node.js process. Under multi-container Docker deployments (as configured in `docker-compose.yml`), a `GET /api/export/[id]` request routed to a different container will return 404 for 50–100% of polls. **Fix:** migrate job state to Upstash Redis (already wired in `src/lib/cache/`). — **10+ weeks unresolved.**

5. **CRON_SECRET fails-open in production when env var unset** — `src/app/api/cron/audit/route.ts:16-21`, `scheduler/route.ts`, `monitor/route.ts`, `geo-monitor/route.ts`, `competitive-snapshot/route.ts`, `retention-purge/route.ts`, `social-scan/route.ts`, `check-predictions/route.ts`, `notifications/digest/route.ts` (10 routes total) — Each route does `if (process.env.NODE_ENV === 'development') return true;` before checking the secret. If `CRON_SECRET` is not set in a production environment (misconfiguration, missed env var), `cronSecret === expectedSecret` evaluates to `undefined === undefined` → `true`, allowing any unauthenticated caller to trigger expensive background jobs. **Fix:** add a hard-fail: `if (!expectedSecret) return new Response('CRON_SECRET not configured', { status: 500 });`. — **New comprehensive count: 10 routes.**

6. **281 TypeScript `any` violations in production code** — Top offenders: `src/app/api/crm/pipeline/route.ts`, `src/lib/browser-query/types.ts`, `src/hooks/usePlatformDashboard.ts` — TypeScript `strict: true` is configured but `any` is used extensively via `: any`, `as any`, `<any>`, and `any[]`. Each is a type-safety hole where runtime errors become invisible to the compiler. **Fix:** enable `"noImplicitAny": true` in ESLint and address violations incrementally, starting with the API layer. — **Methodology corrected from 184 (word-boundary grep) to 281 (type-annotation-specific patterns).**

7. **`admin/api-keys/page.tsx` crosses 1,202 lines** — `src/app/admin/api-keys/page.tsx:1202` — A new entry in the god-file list (joins `schema.ts`, `brands/page.tsx`, `competitor-queries.ts`, `local-payments.ts`, `settings-client.tsx`). 6 files now exceed 1,200 lines.
